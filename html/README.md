# 易助 5.0 KeyGen — HTML/JS 版

纯前端实现，双击 `index.html` 用浏览器打开即可，无需任何依赖、后端或联网。

## 文件

| 文件 | 内容 |
| --- | --- |
| `index.html` | 界面与事件（中文标签都在这里） |
| `keygen.js` | 算法本体，纯逻辑、不碰 DOM，且刻意只用 ASCII，避免脚本编码猜测问题 |

## 界面

界面**完全复刻**原 C# 版（`TPA/Form1.Designer.cs`）：固定 643×610 布局，控件坐标、
尺寸、标签文字、四列功能区排布均按原窗体逐一还原（用绝对定位）。因此它与 PyQt 版
（用 Qt 布局、窗口可缩放）不同，是像素级的原样克隆。

## 算法说明

从已与原版 exe 逐例对拍通过的 PyQt 版（`pyqt/keygen/core.py`）移植，序列号格式：

```
客户代号 - 用户数 - 功能位图 - 各模块用户数 - @@@2 - %%%公司名变换 - 校验和
```

两处在浏览器里需要特别处理，均已在 `keygen.js` 内自带、无第三方库：

* **GBK 编码。** 原版用 `Encoding.Default`（代码页 936）编码公司名。浏览器只有 GBK
  *解码器* 没有编码器，这里在首次使用时用内置 `TextDecoder('gbk')` 把所有合法 GBK
  字节序列解码一遍，反向建出「字符 → 字节」表来实现编码。
* **MD5。** `SubtleCrypto` 不支持 MD5，这里内置了一份对字节数组求 MD5 的实现，输入正是
  公司名等拼接串的 GBK 字节。

## 与原版/其他版本的一致性

`keygen.js` 已在浏览器中用 `pyqt/tools/crosscheck/cases.json` 的全部用例与原版 exe
输出对比，序列号与验证口令均完全一致（含中文公司名、所有功能、用户数进位、`Val`/
`Format` 怪癖等）。

> 若浏览器不带 GBK 解码器（极少见），含中文的公司名将无法正确编码；纯 ASCII 公司名
> 不受影响。
